# 游戏端补丁（可选，但强烈建议）

[English](README.md)

> **这些补丁作用于「游戏本体」，不是插件的一部分。**
> Asphyxia CORE 是服务端——它可以跑在与游戏不同的机器上，
> 插件在架构上无法（也不应该）改动玩家电脑里的游戏文件。
> 所以这一步必须在每台运行游戏的电脑上手动执行一次。

## 需要 Python 环境

```
pip install dnfile dncil
```

## 使用

把本目录放在**游戏所在电脑**上（与 `game/` 目录同级，即项目根目录）：

```
某目录/
├─ game/            ← 游戏本体（spice64.exe 同级）
└─ client-patches/  ← 本目录
```

然后：

```
py patch_all.py            # 施加全部补丁（幂等，可反复运行）
py patch_all.py --check    # 只查看状态
py patch_all.py --revert   # 全部还原（用同目录生成的 .orig 备份）
```

> 脚本按自身位置定位 `../game/svm_Data/managed/`，
> 拷到哪打到哪。换游戏目录后必须重新执行。
> 每个补丁首次运行时都会生成 `.orig` 原始备份。

## 三个补丁分别解决什么

### 1. 更新器异常屏蔽（patch_updater_exception.py）— **强烈建议**

- **文件**：`game.common.contents.dll`
- **不加的后果**：游戏启动时黑屏（`NotUpdateContentsUpdaterException`）。
- **原理**：游戏启动时有一串「内容更新器」要执行，原版逻辑是
  「只要有任意一个没更新成功就抛异常」。本游戏的部分本地 master 表
  （角色卡、剧情、模型等 CSV）在导入环节就有损坏（实测 113 行的
  CharacterCardMaster 只导入 1 行），这些更新器**在任何服务器下都会失败**，
  原版游戏必然黑屏。补丁把「抛异常」改成「忽略」，让启动继续。
- **为什么插件替代不了**：坏数据在游戏自己的资源包（Addressables bundle）里，
  服务端无法修复；而重打包 bundle 会触发游戏的资源校验导致黑屏（已实测两次）。

### 2. 曲目全解禁（patch_music_open.py）— 建议不加时选曲只有一部分

- **文件**：`game.common.contents.dll`
- **不加的后果**：选曲列表里 227 首 Private / 限时曲目被客户端跳过。
- **原理**：取消「非 Open 谱面跳过」的判断。插件的 `usr_item` 已把全部谱面
  道具发给游戏，但客户端还会按曲目数据里的开放状态过滤一次。

### 3. 音频共享模式（patch_audio.py）— 视声卡而定

- **文件**：`game.common.foundation.dll`
- **不加的后果**：部分声卡 / 蓝牙耳机环境下游戏无声。
- **原理**：WASAPI 独占模式 + 自定义格式 → 共享模式 + 设备默认格式。

## 与插件的关系

| 层 | 内容 | 位置 |
|---|---|---|
| 服务端（本插件） | 协议实现、玩家数据、曲目/商店/活动/抽卡数据 | Asphyxia CORE 的 `plugins/` |
| 客户端（本目录） | 修游戏本体自身的缺陷（本地 master 损坏、音频独占、曲目过滤） | 每台游戏电脑 |

两层缺一不可：服务端数据再完整，客户端的导入损坏也得靠补丁兜底。
